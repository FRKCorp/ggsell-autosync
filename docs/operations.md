# Эксплуатация сервера

Как устроен сервер, что делать каждый день (ничего) и что делать, если что-то пошло не так. Все команды выполняются на сервере, в папке проекта (`cd /root/ggsell-autosync`).

## Сервисы

Всё запускается одной командой `docker compose up -d`. Контейнеры:

| Сервис | Что делает |
|---|---|
| `db` | База данных Postgres. Слушает только `127.0.0.1`, снаружи недоступна |
| `app` | Принимает вебхуки GGSell о продажах и обрабатывает заказы |
| `scheduler` | Синхронизация цен (раз в 12 ч), опрос FazerCards по заказам, страховка от потерянных вебхуков, **сторож** |
| `bot` | Telegram-бот администратора |
| `backup` | Ежедневный бэкап БД |
| `caddy` | HTTPS для домена (сертификат Let's Encrypt — сам) |

Все сервисы перезапускаются сами после сбоя или перезагрузки сервера (`restart: unless-stopped`).

## Обновление (деплой)

```bash
git pull --ff-only
docker compose build app scheduler bot
docker compose run --rm app alembic upgrade head
docker compose up -d
curl -s https://ДОМЕН/health
```

Миграции БД (`alembic upgrade head`) — **до** запуска `scheduler`. Он при старте сразу запускает синхронизацию цен, и без новых колонок она упадёт.

После правки `.env` нужно пересоздать контейнеры, обычный `restart` новый `.env` не подхватывает:

```bash
docker compose up -d --force-recreate app scheduler bot
```

## Логи

```bash
docker compose logs --since 1h scheduler      # синхронизация, заказы, сторож
docker compose logs --since 1h app            # вебхуки
docker compose logs --since 1h bot
docker compose logs backup                    # бэкапы
```

Логи каждого контейнера ограничены: не больше 5 файлов по 10 МБ, старые удаляются сами.

## Бэкапы

- Каждую ночь в 03:30 МСК сервис `backup` делает дамп БД в папку `backups/` на сервере (`ggsell_ГГГГММДД_ЧЧММСС.dump`). Хранятся **7 последних**, старые удаляются сами. Время и количество — `BACKUP_AT_UTC` и `BACKUP_KEEP` в `.env`.
- Если свежего бэкапа нет больше 26 часов, сторож пришлёт алерт в бота.
- **Бэкапы лежат на том же сервере.** Если сервер умрёт целиком, они пропадут вместе с ним. Для надёжности стоит время от времени копировать папку `backups/` к себе, например с компьютера: `scp -r root@СЕРВЕР:/root/ggsell-autosync/backups ./`.

**Проверить, что бэкап восстанавливается** (рабочую базу не трогает: разворачивает дамп во временную базу и сверяет число строк):

```bash
docker compose exec -T backup sh /ops/restore_check.sh
```

**Восстановить рабочую базу из бэкапа.** Это заменит текущие данные, поэтому сначала остановите сервисы:

```bash
docker compose stop app scheduler bot
docker compose exec -T backup sh -c 'pg_restore --clean --if-exists --no-owner -d "$PGDATABASE" /backups/ИМЯ_ФАЙЛА.dump'
docker compose up -d app scheduler bot
```

## Мониторинг

**Сторож** (внутри `scheduler`) раз в 5 минут проверяет и пишет в Telegram-бота:

| Проверка | Когда алерт |
|---|---|
| `app` отвечает | не отвечает — вебхуки GGSell не принимаются |
| Бот связывается с Telegram | больше 10 минут нет связи: бот упал или **истёк прокси Telegram** |
| Синхронизация цен | не завершалась дольше 13.5 ч |
| Бэкап | последний старше 26 ч |
| Диск | занят больше чем на 85% |
| Перезапуски | `app`, `bot` или `scheduler` перезапустились (деплой или падение) |

Алерт приходит один раз, когда проблема появилась, и ещё раз — «✅ Восстановлено», когда прошла.

**Чего сторож не видит:** падение всего сервера или самого `scheduler`, потому что тогда сообщить изнутри некому. Для этого нужен **внешний мониторинг** адреса `https://ДОМЕН/health/full`. Он отвечает 200, если БД доступна и `scheduler` жив, иначе 503. Достаточно бесплатного [UptimeRobot](https://uptimerobot.com):
1. New Monitor → тип HTTP(s) → URL `https://ДОМЕН/health/full`, интервал 5 минут.
2. Alert Contacts: e-mail или Telegram.

Тогда, если сервер ляжет целиком, придёт письмо или сообщение от UptimeRobot.

## Фаервол

Входящие соединения разрешены только на SSH (22), HTTP (80) и HTTPS (443). Включается скриптом (идемпотентно, текущее SSH-соединение не рвёт):

```bash
sh ops/firewall.sh
ufw status verbose
```

Если SSH на другом порту: `SSH_PORT=2200 sh ops/firewall.sh`.

## Если что-то сломалось

| Симптом | Что делать |
|---|---|
| Алерт «FazerCards: цены не обновились у N позиций», 403 | Истекла подписка FazerCards — продлить в кабинете FZ |
| Алерт «бот не связывался с Telegram» | Проверить срок прокси (`TELEGRAM_PROXY` в `.env`). После замены — пересоздать контейнеры (см. выше) |
| Заказ на ручном разборе | В боте «⚠️ Ручной разбор»: ответить покупателю (reply на карточку), выдать вручную, закрыть кнопкой «Выдан вручную» |
| Сайт или вебхук не отвечает | `docker compose ps`, `docker compose logs --since 1h app`, `docker compose up -d` |
| Диск заполнен | `df -h`, `docker system prune` (удаляет неиспользуемые образы) |
